1. Resumen Ejecutivo

Este informe documenta el desarrollo completo del backend de la plataforma Kiroku, organizada en tres áreas de responsabilidad técnica, junto con la subsanación integral y verificada de los 8 hallazgos (0 P0, 3 P1 y 5 P2) formulados en el informe docente de revisión del 27 de octubre de 2026.

Todas las modificaciones han sido probadas con casos positivos, negativos y de concurrencia, asegurando el cumplimiento de la consigna y la preparación para la defensa oral del examen final.

2. Proceso de Desarrollo Original por Integrante

👤 Integrante 1 (Maxi) — Autenticación, Usuarios y Seguridad Transversal

  • Infraestructura Base: Conexión central asíncrona a MongoDB Atlas (db.js), variables de entorno validadas (env.js) y script inicializador de administrador (seed.js).
  • Seguridad y Cuentas: Modelo Usuario con contraseñas hasheadas mediante bcrypt (salt 10), protección select: false y sanitización en toJSON.
  • JWT y Roles: Endpoints POST /api/auth/registro (forzando rol STD) y POST /api/auth/login (emisión de token con expiración a 24 horas). Middlewares authToken, authorize (RBAC) y errorHandler centralizado.
  • Administración: Endpoints para listar cuentas, cambiar rol (PATCH /api/usuarios/:id/rol) y eliminación con salvaguarda contra auto-eliminación y chequeo de dependencias relacionales (409 Conflict).

👤 Integrante 2 (Steff) — Catálogo Oficial, Géneros e Ingesta Externa

  • Catálogo y Buscador: Modelo Anime y endpoint GET /api/animes con filtros combinados (texto regex insensible a mayúsculas, género, estado, año y orden) con paginación nativa (skip y limit).
  • Taxonomía de Géneros: Modelo Genero y CRUD exclusivo para administradores, asegurando la existencia de géneros al guardar animes y prohibiendo el borrado de categorías en uso.
  • Operador Atómico $addToSet: Endpoint PATCH /api/animes/:id/generos para agregar etiquetas oficiales sin sobreescribir las existentes ni admitir duplicados.
  • Ingesta Externa Asistida: Endpoint POST /api/animes/importar-externo para importar títulos desde la API de Jikan / MyAnimeList hacia MongoDB Atlas, dotando de soberanía e independencia a la plataforma.

👤 Integrante 3 (Jesu) — Biblioteca Personal, Reseñas y Analítica

  • Biblioteca Personal: Modelo Seguimiento con índice único compuesto { usuario_id: 1, anime_id: 1 }. Gestión de estados (Viendo, Completado, Pendiente, Abandonado) y botón de avance rápido PATCH /api/seguimientos/:id/incrementar (+1 capítulo).
  • Reseñas Comunitarias: Modelo Resena con índice único compuesto (1 reseña por usuario por obra), calificación del 1 al 10 y bandera de spoiler.
  • Pipelines de Agregación:
    • Dashboard propio (GET /api/usuarios/me/estadisticas): horas vistas calculadas (episodios * 24 / 60), desglose por estado y géneros favoritos con $lookup, $unwind y $sortByCount.
    • Rankings comunitarios (GET /api/stats/rankings): Top 10 mejor puntuados y Top 10 más seguidos.

3. Matriz de Hallazgos Docentes y Subsanaciones

Hallazgo 01 · P1 Subsanado

Los permisos sobreviven a la baja o al cambio de rol

Problema Original: authToken validaba el JWT y confiaba ciegamente en payload.rol sin consultar la base de datos. Si un administrador era degradado a STD o eliminado, su token seguía operando con privilegios durante 24 horas.

Subsanación en src/middlewares/auth.middleware.js: Se convirtió el middleware en asíncrono y se agregó la consulta Usuario.findById(id).select('_id email rol nombre'). Si el usuario fue eliminado, devuelve 401 ("Cuenta no encontrada o dada de baja"); si existe, asigna su rol y datos reales extraídos en el momento de la petición.

Hallazgo 02 · P1 Subsanado

Editar el total de capítulos rompe seguimientos existentes

Problema Original: Al editar un anime en PUT /api/animes/:id, se permitía reducir totalEpisodios sin verificar si había usuarios que ya iban por capítulos superiores, rompiendo la coherencia de la biblioteca.

Subsanación en src/controllers/anime.controller.js: Si body.totalEpisodios > 0, se consulta si existe algún seguimiento con episodioActual > totalEpisodios. De existir, se rechaza la operación con 409 Conflict impidiendo la reducción incompatible.

Hallazgo 03 · P2 Subsanado

El estado 'Completado' impedía retroceder solo el episodio

Problema Original: Si un anime estaba en 'Completado' y el usuario enviaba PUT con solo episodioActual: 3, la regla interna forzaba nuevamente el episodio al total, anulando silenciosamente el cambio.

Subsanación en src/controllers/seguimiento.controller.js: Se implementó precedencia: si el usuario retrocede el episodio sin enviar estado, transiciona naturalmente de 'Completado' a 'Viendo'.

Hallazgo 04 · P1 Subsanado

Los episodios admitían números fraccionarios (decimales)

Problema Original: totalEpisodios y episodioActual tenían min: 0 pero ningún validador de entero, admitiendo valores como 2.5 o 12.5.

Subsanación en src/models/Anime.js y src/models/Seguimiento.js: Se agregó el validador validate: { validator: Number.isInteger, message: '...debe ser un número entero' } en ambos modelos y en anioEstreno.

Hallazgo 05 · P2 Subsanado

Afirmación de "recálculo atómico" en el README

Problema Original: La documentación afirmaba atomicidad estricta para dos operaciones separadas (guardar reseña y luego recalcular promedio con aggregate + update).

Subsanación en src/controllers/resena.controller.js y README.md: Se clarificó la documentación explicando que es un recálculo asincrónico por agregación para consistencia eventual, y se restringió la edición de texto exclusivamente al autor original.

Hallazgo 06 · P2 Subsanado

Incrementar el episodio puede perder actualizaciones simultáneas

Problema Original: incrementarEpisodio leía en memoria, sumaba +1 y guardaba con save(). Peticiones simultáneas producían condición de carrera y pérdida de avance.

Subsanación en src/controllers/seguimiento.controller.js: Se reemplazó por una actualización condicional atómica directa en MongoDB con findOneAndUpdate y pipeline condicional, garantizando que dos peticiones concurrentes avancen de forma atómica sin pérdida de datos.

Hallazgo 07 · P2 Subsanado

Errores y rutas inexistentes sin contrato uniforme

Problema Original: Rutas inexistentes devolvían HTML estándar y el error 11000 en el middleware global siempre decía "email".

Subsanación en src/app.js y src/middlewares/errorHandler.middleware.js: Se agregó middleware 404 en app.js devolviendo JSON uniforme ({ error: true, mensaje: "Ruta no encontrada..." }) y se extrae dinámicamente el campo de error.keyValue para indicar el motivo real del conflicto de duplicado (título, género, seguimiento o email).

Hallazgo 08 · P2 Subsanado

La unicidad del título cambia entre alta y edición

Problema Original: El alta validaba títulos con regex case-insensitive, pero la edición solo confiaba en el índice case-sensitive de Mongoose.

Subsanación en src/controllers/anime.controller.js: En actualizarAnime, se valida la unicidad de título con regex case-insensitive excluyendo el ID actual (_id: { $ne: id }), respondiendo 409 Conflict si colisiona.

4. Evidencias de Pruebas Ejecutadas

Prueba / Escenario Petición HTTP Código HTTP Respuesta / Comportamiento Comprobado
Revocación por degradación (H01) POST /api/animes con token de Admin degradado 403 Forbidden { "mensaje": "No tienes permisos..." }. Comprueba rol actual en BD.
Revocación por baja (H01) POST /api/seguimientos con token de usuario borrado 401 Unauthorized { "mensaje": "Cuenta no encontrada o dada de baja" }.
Reducción incompatible (H02) PUT /api/animes/:id con totalEpisodios: 6 habiendo usuarios en cap 10 409 Conflict { "error": true, "mensaje": "No se puede reducir el total a 6 episodios..." }.
Retroceso desde Completado (H03) PUT /api/seguimientos/:id con episodioActual: 3 200 OK Retorna episodioActual: 3 y cambia automáticamente a estado: "Viendo".
Rechazo de decimales (H04) POST /api/animes con totalEpisodios: 12.5 400 Bad Request { "mensaje": "El total de episodios debe ser un número entero" }.
Incremento concurrente (H06) Dos PATCH /incrementar simultáneos desde cap 4 200 OK MongoDB procesa atómicamente ambas peticiones; resultado final exacto: cap 6.
Ruta no montada (H07) GET /api/no-existe 404 Not Found JSON uniforme: { "error": true, "mensaje": "Ruta no encontrada: GET /api/no-existe" }.
Error 11000 descriptivo (H07) Segunda reseña para el mismo anime 409 Conflict { "mensaje": "Ya existe un registro para este usuario y anime" } (no menciona email).
Unicidad case-insensitive (H08) Editar título existente a "NARUTO" existiendo "Naruto" 409 Conflict { "error": true, "mensaje": "Ya existe otra serie registrada con el título 'NARUTO'" }.
