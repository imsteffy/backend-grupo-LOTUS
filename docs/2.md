# Documentación del módulo Catálogo de Animes (Kiroku)

Integrante 2 · Programación III · Repositorio `backend-grupo-LOTUS` · Rama `feature/visualizacion-steff` · Octubre de 2026

## 1. Resumen

Este documento registra todo el recorrido de desarrollo del módulo **Catálogo de Animes** del proyecto Kiroku (Plataforma de Seguimiento y Reseñas de Anime): qué se construyó, qué problemas aparecieron, cómo se resolvieron y qué pruebas se hicieron.

El módulo ofrece un CRUD completo del catálogo, buscador, filtros combinados, paginación y ordenamiento, y un servicio de importación asistida desde APIs externas (Jikan/MyAnimeList con respaldo en AniList). Todo lo importado se persiste en MongoDB Atlas, con géneros y sinopsis traducidos al español.

**Estado final:** módulo terminado, probado y subido a la rama personal. Quedan pendientes la protección de rutas con JWT (depende del Integrante 1), el merge a `main` y el README del grupo.

## 2. Contexto y alcance

El profesor aprobó la temática y pidió una propuesta corregida, con estos puntos que condicionan este módulo:

- Diferenciación estricta de roles (Usuario Estándar y Administrador).
- Profundidad funcional más allá del CRUD básico.
- Explicar cómo se alimenta el catálogo: qué se trae de afuera y qué se persiste localmente (enfoque híbrido).
- Autenticación con JWT, manejo de excepciones con `try/catch` y códigos de estado HTTP correctos.

El trabajo del grupo se dividió en tres módulos:

| Integrante | Módulo |
| --- | --- |
| 1 | Autenticación, JWT, usuarios y roles |
| 2 (este documento) | Catálogo de animes, filtros e integración con API externa |
| 3 | Biblioteca personal, reseñas y estadísticas |

El módulo del catálogo no depende del login para funcionar, así que se pudo desarrollar y probar completo en paralelo. Las rutas de administrador quedaron sin protección a la espera del JWT.

## 3. Recorrido cronológico

### Fase 1. Planificación y propuesta

Se revisó la devolución del profesor y se reescribieron los archivos de la carpeta de planificación (propuesta de frontend, propuesta de backend y resumen) tomando como base la arquitectura en capas del proyecto de referencia `recetorium-backend-kilo`: `app`, `config`, `models`, `controllers`, `routes` y `middlewares`, con ES Modules. Se definió el enfoque híbrido del catálogo y el reparto de roles entre los tres integrantes.

### Fase 2. Esqueleto base y rama de trabajo

- Se armó el esqueleto del proyecto (`package.json`, `src/app.js`, carpetas, dependencias) y se subió a `main`.
- Se creó `.gitignore` para excluir `node_modules` y `.env`, y `.env.example` como plantilla de variables.
- Se creó la rama personal `feature/visualizacion-steff` para trabajar sin pisar a los compañeros.

### Fase 3. Modelo de datos (`src/models/Anime.js`)

Campos y validaciones:

| Campo | Detalle |
| --- | --- |
| `titulo` | Requerido, único, con `trim` |
| `tituloOriginal` | Nombre en japonés o romaji |
| `sinopsis` | Resumen de la obra |
| `generos` | Array de textos, al menos uno |
| `totalEpisodios` | Número mayor o igual a 0 (0 indica emisión o total indefinido) |
| `estadoEmision` | Enum: `En emisión`, `Finalizado`, `Por estrenar` |
| `imagenPortada` | URL del póster |
| `anioEstreno` | Entre 1960 y 2035 |
| `calificacionPromedio` y `totalResenas` | Quedan listos para que el Integrante 3 los recalcule con las reseñas |
| `externalId` | ID de MyAnimeList, con índice sparse |

Además, se creó un índice de texto sobre `titulo` y `sinopsis` para acelerar las búsquedas.

### Fase 4. Controlador (`src/controllers/anime.controller.js`)

Seis funciones, todas con `try/catch` y respuestas HTTP consistentes:

1. `obtenerAnimes`: listado con buscador (`buscar`, insensible a mayúsculas sobre título y título original), filtros combinados (`genero`, `estadoEmision`, `anio`), ordenamiento (`orden`) y paginación (`pagina`, `limite`).
2. `obtenerAnimePorId`: valida el formato del ID y devuelve la ficha o un 404.
3. `crearAnime`: valida duplicados y responde 201.
4. `actualizarAnime`: modifica campos corriendo las validaciones del esquema.
5. `eliminarAnime`: borra la serie.
6. `importarAnimeExterno`: la función principal del módulo (ver Fase 7).

### Fase 5. Rutas y montaje

`src/routes/animes.routes.js` conecta cada verbo HTTP con su función, y `src/app.js` monta el enrutador con `app.use('/api/animes', animesRoutes)`. En el archivo de rutas quedó marcado dónde irán `auth` y `authorize(['ADMIN'])` cuando el JWT esté listo.

### Fase 6. Conexión a MongoDB Atlas

- Se creó un clúster gratuito en Atlas, con un usuario de base de datos y acceso de red habilitado.
- Se armó la cadena de conexión agregando el nombre de la base (`kiroku_db`) y se guardó en el archivo `.env` local junto con `PORT`, `JWT_SECRET` y `JWT_EXPIRY`.
- Verificación: al iniciar el servidor, la consola mostró que Express escuchaba en el puerto 3000 y que Atlas estaba conectado a `kiroku_db`.

### Fase 7. Importación externa y el problema con Jikan

La primera versión de `importarAnimeExterno` consultaba solo la API de Jikan (MyAnimeList). Al probarla devolvió **500**.

**Diagnóstico:**

- Desde el servidor, Jikan fallaba con `UND_ERR_CONNECT_TIMEOUT`, mientras otros sitios (por ejemplo Google) respondían bien.
- La URL tampoco abría desde el navegador ni desde el celular, por lo que el problema no estaba en el código ni en la red local: Jikan no era alcanzable desde esa ubicación.
- Además, el timeout caía en un `catch` genérico y se reportaba como error 500, cuando corresponde un error de servicio externo.

**Solución implementada:**

- Dos fuentes con formato normalizado: `buscarEnJikan` y `buscarEnAniList`. Si Jikan falla por red o servidor, el sistema prueba con AniList (GraphQL, sin clave), que además devuelve el `idMal`, así que `externalId` sigue siendo el de MyAnimeList.
- Timeout de 8 segundos con `AbortSignal.timeout`.
- Códigos correctos: **504** si hubo timeout, **503** si ambas fuentes están caídas, **404** si respondieron pero sin resultados, **409** si el anime ya existe y **400** si falla la validación de Mongoose.
- Corrección de un bug latente: el título se usaba dentro de un `RegExp` sin escapar, lo que rompía con títulos como `Re:Zero (Season 2)`. Se agregó `escaparRegex`.
- Limpieza de la sinopsis de AniList, que viene con etiquetas HTML.

**Resultado:** la importación de Cowboy Bebop respondió **201** con `origenExterno: AniList API`, lo que confirma que el respaldo funciona.

### Fase 8. Traducción de géneros

Los géneros importados llegaban en inglés (`Action`, `Sci-Fi`) mientras que los cargados a mano estaban en español, lo que habría roto los filtros (`genero=Acción`) y las estadísticas del Integrante 3. Se agregó un diccionario `GENEROS_ES` y la función `traducirGeneros`, que además elimina repetidos (por ejemplo `Suspense` y `Thriller`).

Un problema menor: el cambio no se veía porque el archivo no se había guardado. Se resolvió guardando y reiniciando el servidor.

### Fase 9. Traducción de sinopsis

Se pidió que todas las sinopsis estén en español. Para no tocar la estructura compartida del proyecto, la traducción se implementó **dentro de `anime.controller.js`**, sin archivos ni carpetas nuevas:

- `traducirSinopsis` usa el endpoint público de Google Translate, parte el texto en fragmentos de hasta 1500 caracteres respetando las oraciones y elimina notas de fuente como `(Source: ...)`.
- Si el traductor falla, la importación no se rompe: se guarda el texto en inglés y se avisa por consola.

Para los animes ya cargados se usó un script temporal (`traducir-temp.js`). Falló la primera vez porque el modelo se exporta con nombre y no por defecto (`import { Anime }` en lugar de `import Anime`). Corregido ese import, tradujo los 10 registros y luego se borró el script.

### Fase 10. Carga del catálogo

Se importaron animes reales (Naruto, One Piece, Attack on Titan, Death Note, Fullmetal Alchemist: Brotherhood, My Hero Academia, Steins;Gate, Hunter x Hunter, Jujutsu Kaisen, Cowboy Bebop, Demon Slayer y Spy x Family), de modo que el Integrante 3 tenga datos reales para biblioteca, reseñas y estadísticas.

## 4. Endpoints del módulo

| Método | Ruta | Descripción | Rol previsto |
| --- | --- | --- | --- |
| GET | `/api/animes` | Listado con buscador, filtros, orden y paginación | Público |
| GET | `/api/animes/:id` | Ficha de un anime | Público |
| POST | `/api/animes` | Crear anime manualmente | ADMIN |
| PUT | `/api/animes/:id` | Actualizar anime | ADMIN |
| DELETE | `/api/animes/:id` | Eliminar anime | ADMIN |
| POST | `/api/animes/importar-externo` | Importar desde API externa (`{ malId }` o `{ busqueda }`) | ADMIN |

Parámetros de `GET /api/animes`: `buscar`, `genero`, `estadoEmision`, `anio`, `orden` (`calificacion`, `titulo`, `episodios`), `pagina` y `limite`.

## 6. Problemas encontrados y soluciones

| Problema | Causa | Solución |
| --- | --- | --- |
| Error 500 al importar | Jikan inalcanzable (timeout) y `catch` genérico | Fallback a AniList, timeout de 8 s y códigos 503 y 504 |
| Posible 500 con títulos con paréntesis o signos | Título sin escapar dentro de un `RegExp` | Función `escaparRegex` |
| Géneros en inglés al importar | Las APIs externas devuelven inglés | Diccionario `GENEROS_ES` y `traducirGeneros` |
| El cambio de géneros no se reflejaba | Archivo sin guardar | Guardar y reiniciar el servidor |
| Sinopsis en inglés y con etiquetas | Las fuentes no ofrecen español | `traducirSinopsis` con limpieza de HTML y de notas de fuente |
| Script temporal con error de import | Export con nombre, no por defecto | `import { Anime }` |
| Aviso de saltos de línea al hacer `git add` | Conversión LF a CRLF de Git en Windows | Es informativo, no requiere acción |

## 7. Decisiones de diseño (para la defensa)

1. **Catálogo persistido localmente.** Las APIs externas son solo un asistente de carga. Esto da independencia, velocidad y permite relacionar animes con seguimientos y reseñas mediante `_id` propios.
2. **Dos fuentes externas.** Jikan falló desde el entorno de desarrollo y el sistema se recuperó solo, lo que demuestra manejo de excepciones real.
3. **Códigos HTTP precisos.** 400, 404, 409, 503 y 504 distinguen errores del cliente de fallas de servicios externos.
4. **Datos normalizados en español.** Géneros y sinopsis consistentes para que filtros y estadísticas funcionen bien.
5. **Cambios acotados.** Toda la lógica nueva está dentro de `anime.controller.js`, sin alterar la estructura compartida del proyecto.
6. **Credenciales fuera del código.** La cadena de conexión y el secreto JWT viven en `.env`, que está en `.gitignore`.

## 8. Limitaciones conocidas

- AniList devuelve cada temporada como una entrada distinta, por lo que algunos títulos muestran solo los episodios de su primera temporada (por ejemplo, My Hero Academia con 13).
- Las series en emisión, como One Piece, quedan con `totalEpisodios: 0`, que el modelo interpreta como total indefinido.
- La traducción es automática y puede dejar algún nombre propio raro. Se corrige puntualmente con `PUT /api/animes/:id`.
- El endpoint de traducción de Google no es una API oficial; si dejara de responder, la sinopsis se guarda en inglés sin romper la importación. Una alternativa más estable sería una API con clave.
